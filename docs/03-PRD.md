# 3D3S 云授权系统 —— 产品需求文档（PRD）

版本 v4.0.0 ｜ 面向对象：产品、设计、前端 ｜ 基线时间：系统内逻辑时间 2026-03-31

---

## 1. 产品定义

**一句话定义**：面向设计院与工程公司的模块化 CAE 软件云授权管理系统，让企业以「席位池」方式持有 3D3S 各功能模块的使用权，并在组织内部完成分配、回收、审批与成本管控。

**与上一版的根本差异**：授权的所有者由「个人」变为「企业」。个人只是席位的临时持有者。

**边界**：本系统只管授权，不管模块的计算能力。模块内容页复用原有介绍数据。

## 4. 核心对象与字段

### 4.1 席位池 SeatPool

企业为某个模块持有的一批席位。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `orgId` / `moduleId` | string | 一个企业对一个模块最多一个池 |
| `total` | number | 持有席位数。采购或厂商赠予时增加，续费时可增可减 |
| `startDate` / `expireDate` | string | 有效期。过期后席位不可用、不可分配 |
| `source` | `采购` \| `厂商赠予` | 商业版走采购，免费版走赠予 |

> **已分配数不落库**，一律由生效中的 Assignment 实时聚合得出。这样席位账目永远不会对不上。

### 4.2 授权分配 Assignment

池中的一个席位与一个成员的绑定关系。

| 字段 | 说明 |
| --- | --- |
| `poolId` / `memberId` | 绑定关系 |
| `assignedById` / `assignedAt` | 谁在何时分配的，展示在席位池与我的授权页 |
| `revokedById` / `revokedAt` | 回收留痕 |
| `status` | `生效中` \| `已回收` \| `已过期` |
| `usedDays` / `lastUsed` | 使用情况，是利用率判断的依据 |

### 4.3 申请单 Application

| 字段 | 说明 |
| --- | --- |
| `kind` | `SEAT` \| `PURCHASE` \| `QUOTA`，**提交时由系统自动判定，用户不可选** |
| `seats` | 申请席位数。成员固定为 1，管理员可批量 |
| `projectName` | 关联项目，用于后续成本归集 |
| `reason` | 申请理由，最少 5 字，驳回时是申请人调整的依据 |
| `steps` | 审批链快照。**链长度由 kind 决定**，存在单据上而非全局配置，保证历史单据的审批链不受配置变更影响 |
| `status` | 见 5.1 状态机 |

### 4.4 订单 Order

| 字段 | 说明 |
| --- | --- |
| `payMethod` | `在线支付` \| `对公转账`，**决定席位是否需要厂商确认后才发放** |
| `renewPoolId` | 有值表示续费，命中已有池延长有效期并重置席位数；无值表示新增 |
| `applicationId` | 有值表示由申请驱动的采购，到账后自动给申请人分配席位 |
| `status` | `待支付` → `待厂商确认`（仅对公转账）→ `已完成`，或 `已取消` |

## 5. 状态机与流转规则

### 5.1 申请单三分支

判定逻辑（提交瞬间执行）：

```
池存在 且 未过期 且 空闲席位 ≥ 申请数  →  SEAT
否则 模块单价 > 0                    →  PURCHASE
否则                                →  QUOTA
```

| kind | 审批链 | 终态动作 |
| --- | --- | --- |
| `SEAT` | 部门 | 立即从池内分配席位 → `已完成` |
| `PURCHASE` | 部门 → 企业 | 转 `待采购`，等待下单支付 |
| `QUOTA` | 部门 → 企业 → 厂商 | 厂商批准后扩容免费池并分配 → `已完成` |

状态流转：

```
待部门审批 ──通过──▶ [SEAT] 已完成
     │                [PURCHASE] 待企业审批 ──通过──▶ 待采购 ──订单到账──▶ 已完成
     │                [QUOTA] 待企业审批 ──通过──▶ 待厂商审批 ──通过──▶ 已完成
     ├──驳回──▶ 已驳回（任意环节驳回即终止）
     └──申请人撤销──▶ 已撤销（仅限「待部门审批」，即无人处理过时）
```

**边界规则**：SEAT 分支在审批通过的瞬间必须重新校验余量。若提交后余量被他人占满，审批动作应失败并提示"席位已占满，请先扩容或驳回"，不允许超分配。

### 5.2 订单流转与席位到账

```
待支付 ──在线支付──▶ 已完成（席位立即入池）
   │
   └──对公转账──▶ 待厂商确认 ──厂商确认到账──▶ 已完成（席位入池）
   
待支付 / 待厂商确认 ──取消──▶ 已取消（关联申请停留在「待采购」）
```

席位入池时的三种情形：
1. 该企业该模块**无池** → 新建池，有效期 = 今天 + 模块授权天数
2. **有池且为新增采购** → `total += 订单席位数`
3. **有池且为续费**（`renewPoolId`）→ `total = 订单席位数`，`expireDate` 从「今天或原到期日中较晚者」延长一个授权周期

若订单关联申请单，到账后自动给申请人分配 1 个席位（已持有则跳过），并把申请置为 `已完成`。

### 5.3 成员状态与席位的联动

| 动作 | 席位影响 |
| --- | --- |
| 邀请成员 | 状态 `待激活`，无席位 |
| 停用成员 | **自动回收其全部生效中席位**，释放回池，写审计日志 |
| 启用成员 | 不自动恢复席位，需重新分配（避免恢复时池已满） |
| 变更部门 | 席位随人走，不回收（同一企业内资产未流出） |

## 6. 关键页面交互规格

### 6.1 模块中心

- 卡片展示企业席位进度条：`已分配 / 总数`，无池时不显示
- 授权状态徽章四态：`已开通`（我已持有）/ `席位充足` / `席位已满` / `未开通`
- **按钮下方必须预告流程分支**，例如"池内 7 个空闲席位，仅需部门审批"。让用户在点击前就知道要走多久
- 我已持有该模块时按钮禁用为「已持有席位」
- 厂商运营不显示申请按钮（其无 `application:create`）

### 6.2 申请授权（三步）

1. **填写**：顶部用彩色信息条说明本次将走哪条分支及原因；席位数对成员锁定为 1；理由 ≥ 5 字才能下一步
2. **确认**：右侧展示审批链预览（含 PURCHASE 分支额外的「采购与支付」节点）
3. **成功**：显示单号、当前状态、下一环节责任人，并提示可切换身份去处理

### 6.3 审批中心

审批人做决策所需的上下文必须在**同一屏**内呈现：

- 申请人姓名/职称/部门/角色、关联项目、申请理由全文
- 企业该模块席位现状：`已分配/总数，空闲 N`
- 分支后果提示：SEAT → "通过后立即分配，不产生费用"；PURCHASE → "通过后需下单付费扩容"；QUOTA → "通过后由厂商核定免费额度"
- 已完成的审批环节及其意见
- 确认弹窗内再次明确本次操作的**具体后果**（分支 + 当前环节组合，共 5 种文案）
- 驳回**必须填写意见**，通过可不填

### 6.4 席位池

- 顶部四指标：持有总数 / 已分配 / 空闲 / 利用率（利用率 < 60% 转警示色）
- **闲置成本横幅**：`空闲席位数` 与其中商业版对应的年费金额，给出可执行建议
- 进度条颜色三态：占满橙色 / 利用率 < 50% 黄色 / 正常蓝色
- 展开行显示席位持有人，含分配人与分配时间；部门管理员只见本部门持有人并标注"全企业 N"
- 回收弹窗必须写明：谁将失去什么、席位去哪了、历史记录是否保留
- 续费弹窗：席位数下限为在用数；缩减时实时显示节省金额；支付方式影响生效时点

### 6.5 成员管理

- 停用确认必须给出**具体数字**："将自动回收该成员持有的 N 个席位"
- 不能停用或降级自己
- 部门管理员为只读：操作按钮保留但禁用并提示"仅企业管理员可操作"，而非隐藏

### 6.6 订单与账单

- 「待下单采购」区块置顶，列出审批通过待建单的申请，一键下单
- 下单时可采购多于申请数的席位（留余量），弹窗内说明此意图
- 对公转账支付后进入 `待厂商确认`，企业侧显示"等待厂商确认"文案而非可操作按钮
- 厂商视角表头切换为「所属企业 / 模块」，操作列为「确认到账」
