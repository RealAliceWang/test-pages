# UI 设计走查报告

日期：2026-08-27 ｜ 审计基线：[05-design-system.md](./05-design-system.md) 与 [03-PRD.md](./03-PRD.md) 第 7 节 ｜ 方法：8 个专业视角（设计令牌与色彩、字号排版、按钮与徽章、弹窗浮层、表单控件、布局间距、跨页数据呈现一致性、可访问性与动效）并行走查，全部结论基于真实渲染截图 + 源码定位 + 计算样式取值，共产出 60 余条原始发现，去重合并后按主题归纳如下。

## 总体结论

产品的设计底子是好的：令牌集中、组件化程度高（Modal / StatusBadge / MetricCard / SectionCard / .btn-\* / .field 都有全站单源）、语义色有明文含义、可访问性有明确条款。**主要问题不是没有体系，而是体系执行不严**——集中在三类：

1. **绕过体系自造样式**：多个页面在有公共组件/公共类的情况下手写了局部变体（自造按钮、自绘环形、自写利用率阈值、自拼徽章），造成同一概念跨页多种长相。
2. **近期迭代与规范文档脱节**：signal 色已从柠檬绿换成浅蓝但文档未更新；KPI 数字从规范的 34px 改到 40px 打平了与身份卡的层级；上一轮 UX 修复新增的控件（日期筛选、导出按钮、周期下拉、原因输入框、"已满"徽章等）多数没有对齐既有控件规格。
3. **两处全局性 CSS 缺陷**放大了观感问题：`*:focus-visible` 会把任何控件聚焦瞬间改写成 12px 圆角（正圆按钮、胶囊搜索框全部变形）；textarea 只挂 `.field` 时继承 999px 胶囊圆角，四行文本域渲染成"体育场"。

| # | 问题 | 证据 | 修复 |

## 中/低严重度问题（择要，共 30 余项）

**排版**：全站 11 种非法字号共 40+ 处（合法集合为 12/13/13.5/14/15/16/20/26 + 27/34/40 三个专属值），11.5px 表头、12.5px 已成"影子阶梯"；个人信息页 4 张卡标题 16px 加粗（规范 13.5px，且是规范反面清单点名写法）；"应付金额"在三个付费弹窗里 32px 与 20px 两种规格；Modal 标题 17px 不在梯级内。→ 全部归位。

**表单**：筛选行控件 38px 与 32px 两档并排顶边不齐；新增日期输入保留原生黑色日历图标、空值深色像已填值；统计周期下拉手写圆角胶囊不走 .field；厂商调价数字输入是全站唯一带灰边框的输入；表单标签 13/14/14bold 三种规格；理由计数器永远 placeholder 灰且不随校验失败变色。→ 统一 .field 单源 + 标签 13px 契约 + 计数器不足 5 字转 warning。

**弹窗**：底部按钮三种排布（右对齐取消在左 / 左对齐主键在左 / 等宽铺满）→ 契约统一右对齐、取消在左；回收与停用两个"原因/备注"输入框标签字号与按钮排布不一致 → 统一。

**徽章/图标**："已满"徽章手写 10.5px（低于全站最小合法字号）→ 归位 StatusBadge；"代部门审批"标签两套实现 → 固化唯一写法；lucide 图标 size 12/13/14/15 混用 → 按钮内统一 14；审计日志把五个语义状态色当日志分类调色轮（"邀请成员"顶着与"待审批"相同的琥珀）→ 分类改中性灰胶囊。

**布局**：统计页 KPI 网格 gap 16px 与全站 20px 不一致；空态三种形态（圆形灰底图标 / 裸图标 / 纯文字）→ 统一圆形灰底形态；"浅蓝底蓝字"按钮成为体系外第五种按钮 → 归位 .btn-soft/.btn-accent。

**对比度**：orange 文字档 #EA580C 白底 3.56:1（文档自称 4.5:1）→ 调深；danger 文字在 danger-bg 上 4.41:1 → 微调；变更角色高风险警示条受益于同一修正。

**可访问性**：厂商目录 12 个上下架 Toggle 无可访问名称；行内三点菜单 28×28px 低于 36px 底线；Modal 关闭钮 32px。→ 传 aria-label / 撑大点击区。

**文档失真**：设计文档 §1/§2.1/§5.9/§8 仍整章描述已被替换的柠檬绿 signal 体系 → 同步为当前浅蓝体系，并补录本轮新契约（meter 令牌、.btn-accent、按钮双档高度、弹窗按钮排布、"代部门审批"标签规格等）。

**本轮暂不处理**（记录在案）：审批链时间线三种形态的彻底统一（申请人图形时间线 / 审批人纯文本 / 预览编号列表）仅做轻量语义色增强，完整重构留待下期；人员单元（头像 28-46px 五档字号）的统一涉及 6+ 页面联动，建议抽 PersonCell 组件后一次到位；统计页与席位池的内容重复属信息架构议题，前轮已评估保留。
