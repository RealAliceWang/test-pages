3D3S 云授权系统

为建筑结构工程软件设计的 B 端云授权管理平台，涵盖模块发现、试用申请、商业采购、使用管理的完整用户旅程。

向下滚动浏览
01 — 项目概述
从线下流程到线上闭环

3D3S 是面向建筑结构工程领域的专业分析软件，包含 18+ 个功能模块。此前授权管理依赖线下沟通，我们需要设计一个让用户能自助完成从「模块发现 → 试用/采购 → 使用管理」完整闭环的云端平台。

🎯

设计目标

打造「高效、透明、专业」的云端授权管理平台，覆盖普通用户和管理员双角色场景，支持模块试用、商业采购、授权管理、数据洞察四大核心功能。

👥

目标用户

结构工程师（日常使用模块进行建模分析，关注授权状态和到期时间），以及 IT 管理员（审批试用申请、监控全局使用数据、管理用户权限）。

🔄

设计方法

采用双钻石设计流程：竞品分析 + 用户访谈 → 信息架构 + 用户流程 → 视觉系统 + 高保真原型 → 交互细节 + 可用性验证。

📐

核心约束

B 端工程软件用户对「专业感」和「信息密度」要求高，界面需要在保持美观的同时确保高效的信息传达，避免过度装饰。

02 — 问题发现
5 个核心痛点

通过用户访谈和业务分析，我们识别出影响授权管理体验的 5 个关键痛点。

01

试用申请周期过长

模块试用需线下沟通，邮件审批流程 3-5 天，用户等待成本高，导致试用转化率低。

影响：用户流失率 ↑
02

采购流程割裂

付费模块购买需要线下签合同，缺乏统一的线上支付和订单管理系统。

影响：收入转化率 ↓
03

授权状态不透明

用户无法实时查看模块到期时间，频繁通过客服渠道咨询，增加运营负担。

影响：客服工单量 ↑
04

管理视野缺失

管理员缺乏使用数据可视化工具，无法了解部门级使用情况和模块利用率。

影响：决策效率 ↓
05

订单追踪困难

试用申请和购买订单分散在邮件和 Excel 中，缺乏统一记录和审批追踪。

影响：流程透明度 ↓
→

设计机会

设计一个统一的云端平台，将模块发现、试用/采购、授权管理、数据洞察整合为完整闭环。

策略：自助化 + 可视化
03 — 用户研究与画像
用户画像与竞品洞察

对标分析了 JetBrains、Autodesk、阿里云等平台的授权管理模式，结合用户访谈构建了核心用户画像。

👨‍💻
王工
结构工程师 · 普通用户

目标：快速找到需要的模块 → 申请试用 → 查看授权状态和到期时间

痛点：不知道有哪些模块可用，到期了没人提醒，试用申请后等很久也不知道进度

关键洞察：「我更关注模块还剩多少天能用，而不是它有哪些功能参数」

日常使用 3D3S 关注到期时间 偏好自助服务 手机 + 桌面端
👩‍💼
李管理
IT 部门负责人 · 系统管理员

目标：审批试用申请 → 监控全公司使用情况 → 管理用户权限

痛点：看不到全局使用数据，不知道哪个部门在用哪些模块，审批信息散落在邮件中

关键洞察：「我最常被问的就是'某某模块还有几个节点可以分配'」

07 — 交互设计
交互设计模式

12 种精心设计的交互模式，每一种都有清晰的使用场景和设计理由。

✏️

行内编辑

个人信息页 — 姓名/手机/邮箱

点击铅笔图标切换为输入框，配合确认/取消按钮。避免跳转编辑页，保持用户上下文不被打断。

📋

弹窗表单

模块中心 — 试用申请 / 订单记录 — 订单详情

轻量级操作使用弹窗承载，不打断用户的浏览流。包含表单验证和温馨提示，降低错误率。

🔢

步骤向导

购买流程 — 3 步购买流程

复杂的采购流程分为「填写信息 → 确认支付 → 购买成功」三步。步骤指示器让用户始终知道自己在哪。

🔄

角色演示切换

顶部栏 — 全局角色切换

管理员(橙色) ↔ 用户(蓝色) 一键切换视角。让利益相关者在评审时体验双角色，降低沟通成本。

📊

语义化色彩编码

全局 — 状态标签、数据卡片、环形进度

蓝=正常/激活, 绿=成功/通过, 橙=警告/付费, 红=错误/拒绝, 灰=过期/禁用。全系统语义一致。

⬆️

悬停微交互

模块中心 — 卡片网格

卡片悬停时上浮 2 像素 + 阴影加深，通过微妙的物理隐喻暗示可交互性，提供即时视觉反馈。

⏱

支付倒计时

购买流程第二步 — 15 分钟倒计时

右上角实时倒计时制造适度紧迫感，提高支付完成率。配合安全提示条降低焦虑。

📋

一键复制

购买流程 — 订单号、银行账号

一键复制关键信息，复制后图标变为 ✓ 提供确认反馈。减少手动输入错误，提升 B 端场景效率。

09 — 项目复盘
项目复盘

做得好的地方

  • 通过自定义属性建立设计令牌，实现全系统色彩和间距的统一管理
  • 管理员/用户角色在同一框架下差异化展示，减少开发两套界面的成本
  • 从模块发现 → 试用/采购 → 使用管理的完整闭环设计，用户旅程清晰无断点
  • 状态驱动的色彩语义体系（蓝/绿/橙/红/灰）在全系统保持一致性
  • 3 步购买向导 + 预填数据 + 安全提示，有效降低 B 端采购转化摩擦

待改进的方向

  • 响应式断点处理不够系统化，目前以桌面端为主，移动端适配待完善
  • 使用统计页时间范围筛选仅为界面展示，需接入真实数据接口
  • 缺少骨架屏加载状态，可进一步提升感知性能
  • 可增加新手引导流程帮助新用户快速上手
  • 暗色模式可作为下一迭代方向
